## The finding that matters

**The specification was the weak link, not the model.**

The owner's first reaction to the finished app was that there was no way to generate a program —
no schema to download, no prompt to copy. That is correct, and it is a defect in the
specification. `06 §6.3` defined `#/programs` as, in full, _"Upload control accepting a `.json`
file."_ The only mentions of the authoring prompt anywhere in `specs/` are cross-references to a
markdown file in the repository. Grepping the implementation for any schema or prompt affordance
returns only its two internal imports of the schema.

The authoring journey the specification actually described was: open GitHub on your phone, find
`fixtures/authoring-prompt.md`, copy 200 lines of markdown, paste into an LLM. Standing in a gym.

The implementation matched the specification faithfully. The rubric cannot deduct for it, and
should not. But an implementation can score 99/100 and still be unusable for its stated purpose —
which is a fact about the rubric, not about the model.

Addressed in
[`../specs/11-amendment-001-program-authoring.md`](../specs/11-amendment-001-program-authoring.md),
which does not apply retroactively to this run.

Related: the specification declared no visual direction at all, so any coherent aesthetic
satisfied it. The industrial "Fieldwork" direction is the implementation's own choice, recorded
in `DECISIONS.md`. Amendment 001 §11.4 adds checkable visual constraints without prescribing a
look.

## Assessment

On the narrow question — _can this model implement a demanding specification in one pass?_ — the
answer here is yes, convincingly. It handled every case built specifically to catch shortcuts,
including the two most commonly missed: optimistic UI that survives a failed write, and CSV
export that resolves prescriptions against the current program instead of the logged one. It
enforced its own architectural boundaries in lint rather than merely documenting them. It wrote a
`DECISIONS.md` recording genuine specification silences and nothing else.

The honest caveat is that this result says as much about the specification as about the model.
The traps were gradeable because they were written down. A vaguer brief would have produced a
vaguer result — and, as this run demonstrates, a brief can be precise, fully satisfied, and still
wrong about what the product needed.
